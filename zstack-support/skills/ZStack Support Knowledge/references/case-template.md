## 目录命名

```text
cases/YYYYMMDD-客户或项目主题/
```

一个独立支持问题对应一个案例目录。目录名在共享前替换客户或项目名称；独立问题拆分后在 `notes.md` 中交叉引用。

## 推荐结构

```text
case-directory/
  raw/          # 仅本地，不提交
  extracted/    # 仅本地，不提交
  outputs/      # 脱敏且批准后才可分享
  notes.md
  final_report.md
```

## 关键断言表

```markdown
| ID | 关键断言 | 公开标签 | 成熟度 | 来源类型 | 来源定位 | 能支持的范围 | 不能支持的范围 |
|----|----------|----------|--------|----------|----------|--------------|----------------|
| A1 | | 已确认/较可能/可能/证据缺失 | E0-E5 | 当前事件/GitHub/官网文档/BBS/Tavily或公开Web/Jira/Confluence | | | |
```

来源类型和成熟度必须分别填写。修复提交、发布版本或 Jira 关闭本身不得标为 E5；E5 仅用于当前事件处置后的恢复验证与约定复测闭环。

## 参考证据块

```markdown
### 参考证据块

- 来源类型：GitHub / 官网文档 / BBS / Tavily或公开Web / Jira / Confluence
- 来源状态：工具可见 / 已连接 / 结构化查询成功 / MCP 查询未完成 / 已配置但未注入 / 未配置
- 查询词：仅记录去标识化后的词
- 命中摘要：
- Ref、版本或页面日期：
- 路径或章节：
- 链接：
- 相关性：高 / 中 / 低
- 证据成熟度：E0-E5
- 公开标签：已确认 / 较可能 / 可能 / 证据缺失
- 能支持的判断：
- 不能支持的判断：
- 当前事件仍需验证：
```

`internal` 事件分析或交接必须记录已命中的 BBS/Jira/Confluence 编号、标题摘要和合规 Markdown 直达链接；完整 URL 不可得时记录“直达链接未返回”，不得猜测。`customer` 交接禁止内部链接、内部端点、原始页面、评论、附件和内部标识，只保留可由对外证据支持的脱敏结论与行动建议。
