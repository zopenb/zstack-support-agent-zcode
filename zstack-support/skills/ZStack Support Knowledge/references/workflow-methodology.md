# 渠道支持工作流方法论

本文件定义 Intake、证据模型、行动建议和闭环模型。来源选择以 [查证路由规则](evidence-routing.md) 为准；不得在这里另建固定查询顺序。

## 工作流

```text
入口判断
→ 当前事件 Intake
→ 提取去标识化故障指纹
→ 具体支持事件首批查证 BBS、Jira 和 Confluence；源码/版本类同批加入 GitHub
→ 映射关键断言、来源类型和证据成熟度
→ 给出客户安全行动
→ 记录多维闭环决策
```

完整报告只在用户明确要求完整分析、根因、闭环、交接或研发材料时生成。快速口径可省略案例目录等字段，但不能省略关键断言的标签、成熟度和边界。

## Intake

```text
故障对象：
观察到的症状：
影响范围：
时间窗口：
产品/版本证据：
最强静态错误信号：
关键对象类型（不记录客户标识值）：
最小缺失证据：
```

证据不足时只请求会改变下一步路由或结论的最小信息。不要为填写模板而索取客户名、项目名、UUID、IP、账号、主机名或完整日志。

## 证据二维模型

来源类型与证据成熟度是两个独立维度。不得把某种来源绑定到特定成熟度，也不得因为来源是 GitHub、官网、Jira 或 Confluence 就自动提高或降低成熟度。

### 维度一：来源类型

| 来源类型 | 典型内容 | 固有边界 |
|----------|----------|----------|
| 当前事件 | 客户陈述、截图、日志、命令/API 输出、现场复现、修复后验证 | 唯一能证明当前事件状态的来源 |
| GitHub | 公开源码、commit、PR、tag、branch | 证明公开实现或版本事实，不证明现场实际路径 |
| 官网文档 | 官方配置、限制、步骤、功能边界 | 证明文档口径，不证明现场符合条件 |
| BBS | 历史案例和处置经验 | 证明历史记录，不证明当前事件相同 |
| Tavily/公开 Web | 厂商、OS、开源生态资料 | 证明公开参考，不证明当前 ZStack 事件 |
| Jira | 内部缺陷/需求状态和版本元数据 | 证明内部跟踪事实，不证明代码合入或现场命中 |
| Confluence | 内部口径、兼容边界和规范 | 证明内部文档事实，不证明现场根因 |

连接状态（如“结构化查询成功”）也不是证据成熟度，只描述工具是否可用。

### 维度二：证据成熟度 E0-E5

| 级别 | 定义 |
|------|------|
| E0 | 没有可指向的证据项，仅为假设 |
| E1 | 只有未独立核验的陈述、截图转述或二手摘要 |
| E2 | 有一个可检查的当前产物或一个可检查的参考来源，能支持范围有限的事实，但尚未与其他证据关联 |
| E3 | 至少两个相互独立的证据项对同一限定断言一致，并已核对关键适用条件；仍未建立完整因果链 |
| E4 | 通过完整当前事件证据链或受控复现建立因果关系，并在声明范围内排除了主要替代解释 |
| E5 | 对当前事件执行修复、回退或处置后，完成恢复验证及约定观察/复测，确认目标症状消失且验收条件满足 |

E5 只表示当前事件验证闭环。以下事实本身都不是 E5：

- 修复代码已提交或合并；
- Jira 已关闭或填写 fixVersion；
- 新版本已发布；
- 历史案例复测通过；
- 文档声明问题已修复。

这些来源可以支持“修复存在、版本包含、工单状态”等限定断言，但只有当前事件完成处置后验证才能达到 E5。

### 公开标签

标签描述断言措辞，不替代成熟度：

| 标签 | 使用方式 |
|------|----------|
| 已确认 | 证据直接支持该断言的限定范围；可用于 E2 的源码/状态事实，但最终根因通常仍需 E4 |
| 较可能 | 多项线索一致，但因果链或适用条件仍有缺口 |
| 可能 | 有方向性证据，仍存在明显替代解释 |
| 证据缺失 | 当前没有可支持该断言的证据 |

约束：

- E0-E2 不得作为当前事件最终根因；E2 可以确认范围有限的来源事实。
- E3 可以形成优先级较高的诊断判断，但不能假装完成因果证明。
- 当前事件根因通常需要 E4。
- 状态“已关闭”必须为 E5；修复发布但客户未验证时保持“待客户验证”或“监控中”。

## 断言与证据映射

每个关键断言至少记录：

```text
断言 ID：
断言：
公开标签：已确认 / 较可能 / 可能 / 证据缺失
证据成熟度：E0-E5
来源类型：当前事件 / GitHub / 官网文档 / BBS / Tavily或公开Web / Jira / Confluence
来源定位：时间戳、产物位置、文件/commit、页面或工单摘要
能支持的范围：
不能支持的范围：
待补证：
```

一个断言可以引用多个来源；每个来源保留自己的类型和边界。不要用“多来源”这个词掩盖来源并不独立或都转述同一事实的情况。

查询和输出安全以 [查证路由规则](evidence-routing.md) 与 [渠道安全策略](security-policy.md) 为准。外部来源只能收到去标识化故障指纹。

## 安全行动

默认给只读、可回退或客户安全的验证步骤：

```text
目的：
执行位置：
只读：是 / 否
命令或操作：
预期输出：
异常解读：
风险：
```

涉及重启、删除、迁移、数据库修改、网络切换、升级或其他状态变更时，先给受保护计划并等待明确授权：

```text
高风险操作：
影响范围：
业务中断：
前置检查：
备份与回滚：
执行窗口：
执行步骤：
后置验证：
中止条件：
```

涉及日志路径时引用 [日志路径基准](log-paths.md)，未列出的组件先用只读命令定位。

## 多维闭环决策

闭环不再使用一个混合枚举同时表达状态、处置和产物。分别记录以下四个维度。

### 状态（单选）

```text
收集中
诊断中
待客户验证
待研发决策
监控中
已关闭
```

### 处置（多选）

```text
补充证据
客户验证
临时规避
追踪已知缺陷
新缺陷草案
研发决策
分析修订
质量治理
知识更新
无需额外处置
```

### 分类（多选）

```text
产品缺陷
配置或操作
外部环境或第三方
预期行为
数据或证据问题
尚未分类
```

### 产物（多选）

```text
客户回复口径
验证计划
临时规避方案
缺陷提报材料
变更方案
故障报告
交接摘要
知识条目
无
```

闭环块：

```text
闭环状态（单选）：
处置（多选）：
分类（多选）：
产物（多选）：
当前最高证据成熟度：
责任人：
客户安全下一步行动：
剩余缺失证据：
关闭验收条件：
```

“临时规避、追踪缺陷、知识更新”等不是状态。“已关闭”只能在当前事件达到 E5 且关闭验收条件已满足时使用。

## 案例更新与交接

新证据改变结论时追加更新，不覆盖历史判断：

```text
更新时间：
来源类型：
变更内容：
证据成熟度：
公开标签：
闭环状态变化：
下一步行动：
责任人：
```

交接时必须携带受众、关键断言表和多维闭环块，使接收人能区分现场事实、参考事实、推断和未完成项。格式见 [案例模板](case-template.md)。
