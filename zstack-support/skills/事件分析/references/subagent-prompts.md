# 显式 subagent 并行深查模板

只有用户明确要求多 agent、subagent 或并行深查，且任务能拆成至少两个互不覆盖的有界子任务时使用。普通事件分析由主 agent 完成。不预设 agent 数量，也不设置来源数量门槛。

## 派发前决策

1. 具体支持事件把 BBS、Jira 和 Confluence 作为首批内部来源；涉及源码或版本时同批加入 GitHub。低风险直答、明确单点求证或无有效故障指纹时按路由例外处理。
2. 把客户材料转换成去标识化指纹；删除 UUID、IP、账号、客户/项目/主机名、域名、邮箱、序列号、许可证标识和原始日志上下文。
3. 合并高度相关的来源组，保证每个子任务边界互斥。
4. 获取当前可用并发槽位；主 agent 占一个槽位，派发数不得超过剩余槽位。
5. 只派发会缩短关键路径的任务；其余由主 agent 完成。

可选来源组，不是固定清单：

```text
源码/版本：仅 GitHub 源码、commit、tag、release branch、调用链和版本差异。
历史案例：仅 BBS 相似案例、差异和可复用验证动作。
内部跟踪/口径：具体支持事件查询 Jira 和 Confluence；明确单点例外只查用户指定来源。
文档/外部：仅本次触发的官网文档和/或 Tavily/厂商资料。
```

## 动态调度模板

```text
请并行深查此 ZStack 支持事件。

事件边界：<不含客户标识的摘要>
可查询故障指纹：<仅静态错误模板、类/API/配置键、组件和公开版本>
需要回答：<限定问题>

按本次路由派发以下有界任务：

<仅列实际需要的任务，每项包含>
- 任务名：
- 唯一来源范围：
- 禁止扩展的来源：
- 查询词：已去标识化
- 需要返回的限定事实：
- 不能下的结论：

派发数量不得超过当前剩余并发槽位。主 agent 继续整理当前事件证据和最终合并。
等待所有影响结论的任务；超时或失败写“查证未完成”，不得写成“未命中”。
```

## 子任务输出

```text
来源类型：
来源状态：
查询词：仅脱敏词
命中摘要：
链接：
相关性：高 / 中 / 低
证据成熟度：E0-E5
公开标签：已确认 / 较可能 / 可能 / 证据缺失
能支持的判断：
不能支持的判断：
证据边界：
未完成项：
```

内部任务不得输出原始正文、评论、附件、账号、Token、Authorization 或 MCP 载荷。`internal` 子任务命中 BBS/Jira/Confluence 时必须返回标题摘要和 Markdown 可点击直达链接；完整 URL 不可得时写“直达链接未返回”，不得伪造。客户输出不得包含 BBS/Jira/Confluence 链接或内部端点。

## 降级输出

仅当用户明确要求并行但未能派发时输出：

```text
Subagent 状态：未触发
原因：当前会话未暴露调度工具 / 宿主策略不允许 / 任务不可拆分 / 可用并发不足 / 调用失败
降级动作：由主 agent 完成本次实际需要的来源查证
```
