# BBS 经验回流

把已完成问题的处理经验沉淀为可检索、可复现、边界明确的 BBS 知识。AI 负责理解上下文、判断缺口、组织内容和选择插入位置；不要用脚本或固定问卷替代判断。

## 进入条件

- 优先从当前会话、事件分析、故障报告、变更方案和用户已提供材料中提取信息，不重复询问已有答案。
- 问题尚未恢复、关键验证未完成或结论仍在变化时，可以生成草稿，但必须标记“暂不具备发布条件”。不要为了发帖把事件写成已关闭。
- 用户提供的提纲默认是写作方向，不是必须逐字照抄的正文。

## 工作流

### 1. 建立事实底稿

先在内部整理以下内容，并区分“当前事件事实”“参考资料”和“AI 归纳”：

- 产品、版本、组件、部署形态及必要前置条件；
- 问题现象、影响范围、触发条件和稳定错误信号；
- 关键排查过程、排除项及其证据；
- 根因或原因边界，以及结论成熟度；
- 实际执行的处理步骤、关键参数、顺序和中止条件；
- 恢复结果、验证方法、验证范围和观察时长；
- 适用范围、不适用场景、风险、回退或替代路径；
- 可公开引用的版本、文档、缺陷或历史知识。

不得把计划执行、建议执行或参考案例中的动作写成现场已执行。无法确认根因时可以写“根因未最终确认”，但必须准确记录已确认的现象、有效处置和适用边界。

### 2. 查重与冲突检查

使用去标识化关键词通过 BBS 只读工具搜索相同错误、组件、版本和处理路径。比较候选帖的症状、前提、根因、操作和版本边界：

- 已有帖子内容完整且一致：优先建议补充原帖，不重复新建；
- 已有帖子部分相同：说明本次新增价值和差异，再决定补充或新建；
- 结论冲突：列出冲突和待核实项，未澄清前不得发布；
- 工具不可用：标记“BBS 查重未完成”，不得声称无重复帖子。

查重查询不得发送客户名、项目名、账号、IP、UUID、主机名、完整日志、截图、许可证或凭据。

### 3. 完整性审核和精准追问

按对后续读者是否会产生错误操作来判断缺口，不机械要求所有字段齐全。

发布必需项：

- 能被检索的问题标题和稳定症状；
- 会影响结论或操作的版本、组件和前置条件；
- 已确认的最终处置，且与建议、尝试项明确分开；
- 处置后的验证结果和验证方式；
- 根因成熟度与适用边界；
- 不包含凭据和不必要的客户标识。

推荐项包括完整时间线、无效尝试、观察时长、回退方式、关联资料和责任人。缺少推荐项不应一律阻止发布，但要说明对知识质量的影响。

只追问当前上下文无法推导且会影响正确性的细节。每轮最多提出 3 个聚合问题，按影响排序，并说明缺失会造成什么误导。允许用户明确回答“未知”“未验证”或“不适用”；不得反复逼问，也不得替用户编造。

### 4. 编写审核稿

根据实际案例组织内容，不为空字段保留章节。默认结构如下，可按问题类型调整：

```markdown
# 标题

## 适用范围
## 问题现象与影响
## 关键错误或证据
## 排查过程
## 原因分析
## 处理方法
## 验证结果
## 风险、回退与注意事项
## 参考信息
```

要求：

- 标题包含可检索的组件、动作或错误特征，不包含客户名和项目名；
- 命令只保留必要片段，变量使用明确占位符，并说明执行位置、预期结果和风险；
- 截图只在能直接证明相邻结论且已脱敏时使用，紧跟对应现象、错误或验证步骤；不要集中堆放图片；
- 引用 BBS/Jira/Confluence 时只总结支撑范围，不搬运原始正文、评论、附件或原始 MCP 载荷；
- 不把单个现场经验无条件推广到所有版本或环境。

### 5. 发布门禁

先展示完整审核稿，并附简短审核结果：

```text
回流状态：可发布 / 待补充 / 存在冲突 / 查重未完成
关键缺口：
查重结论：
建议板块与标签：
脱敏结论：
```

只有状态为“可发布”、查重已完成且用户看过最终标题、正文、板块和标签后，才询问一次明确发布确认。用户修改任何正文后，重新执行完整性、冲突和脱敏检查；不得沿用旧确认。

“整理一下”“生成草稿”“看看是否完整”不等于授权发布。只有“确认发布”“按这版发布”等对当前审核稿的明确表达才是发布授权。

### 6. 受控发布与回读

优先使用当前插件明确批准的 `bbs_create_thread`。该工具固定发布到 `fid=114`；调用前必须展示最终标题和正文并获得当前版本审核稿的明确发布确认。不得猜测工具名或尝试其他写工具，不得直接调用远端 HTTP 接口或临时修改插件白名单。

没有受控 BBS 写工具时，如当前环境提供已登录的浏览器控制能力，可在用户已确认当前审核稿后通过 BBS 页面发布；不得在聊天中索取账号或密码。浏览器不可用或未登录时，交付可直接发布的审核稿并明确写“当前环境未执行 BBS 发布”。

发布后必须回读帖子页面，核对标题、板块、正文完整性和图片位置，返回真实可点击链接。发布调用成功但无法回读时写“已提交，回读验证未完成”，不得声称发布验证通过。

## 安全边界

- BBS 回流按内部知识发布处理，但最小化原则仍适用。默认移除客户名、项目名、真实 IP、UUID、主机名、账号、许可证、客户截图和无关业务数据。
- 严禁发布 Token、密码、Authorization、私钥、Cookie、完整配置密钥、原始 MCP 载荷或未经批准的客户材料。
- 必须保留技术判断所需的版本和组件信息；不能以脱敏为由删除关键适用条件。
- 发布前调用 `@ZStackSupport:脱敏检查` 按 `internal` 受众复核。未通过不得发布。
- BBS 回流是知识沉淀，不替代 Jira 缺陷提报、故障报告、变更审批或当前事件的 E5 验证闭环。

## 最终输出

未发布时返回审核状态、缺口或审核稿，不暗示已经回流。发布成功时返回：

```text
回流状态：已发布并回读验证 / 已提交但回读验证未完成
帖子标题：
帖子链接：
板块与标签：
本次新增知识：
仍需后续维护：
```
