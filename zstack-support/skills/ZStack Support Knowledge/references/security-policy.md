# 渠道安全策略

安全判断必须先区分受众：`internal` 表示公司内部渠道协作，`customer` 表示可直接发给客户。两者都禁止凭证和不必要的客户原始数据；内部链接、内部标识和文档元数据的处理不同。

## 受众边界

| 内容 | internal | customer |
|------|----------|----------|
| BBS/Jira/Confluence 编号、标题摘要、完整链接 | 查证命中时必须输出标题摘要和 Markdown 可点击直达链接；只保留判断所需字段 | 禁止内部链接和内部端点；仅保留可由对外证据支持的脱敏结论 |
| 内部操作说明 | 可保留必要摘要 | 只保留客户可执行且已批准的步骤 |
| 客户标识与原始证据 | 默认删除；确有排障必要时最小保留并限制渠道 | 默认删除或泛化；仅在直接交付给同一客户、用户明确确认且版式确有需要时，最小保留该收件客户自身的名称、项目名或联系人，不得夹带第三方标识或原始证据 |
| 内部 IP、账号、主机名和系统拓扑 | 除受控例外外删除 | 禁止 |
| 凭证、许可证密钥、Token、Cookie、Authorization | 禁止 | 禁止 |

不得使用无受众限定的“可安全分享”。检查结果必须写“可在 internal 渠道分享”或“可向 customer 分享”。`customer` 不等于可公开传播；保留收件客户自身标识的文件只能通过已批准渠道直接发给该客户，不能复用于其他客户、公开材料或跨客户案例。

## 受控 HTTP 端点例外

插件当前使用 Atlassian 共享端点 `http://172.18.250.27:3340/mcp`。这是已知、受控的内部配置例外，只允许出现在：

- 插件 `.mcp.json`、`agents` 依赖元数据和连接器校验规则；
- 内部安装、连通诊断和运维文档；
- `internal` 受众下为定位连接问题所必需的最小配置摘要。

该例外不代表 TLS、加密传输或链路保密已经建立。禁止在客户输出、客户案例材料、故障报告正文、交接给客户的文档或公开资料中出现该 IP/URL。除这一明确端点外，不允许未批准的内部 IP 或端点。

## 外部与内部查询

GitHub、Tavily、公开 Web 和厂商论坛查询前必须删除客户/项目/租户名称、UUID、IP、账号、主机名、域名、邮箱、序列号、许可证标识和原始日志上下文，只使用静态错误模板、类/方法/API、配置键、组件和必要公开版本号。

BBS、Jira 和 Confluence 查询也执行最小化：优先静态故障指纹，不发送完整日志、附件、凭证或与检索无关的客户标识。详细规则见 [查证路由规则](evidence-routing.md)。

`internal` 为事件分析默认受众。BBS 命中使用完整 tid URL，Jira 命中使用完整 browse key URL，Confluence 命中使用 MCP 返回的完整 URL；无法获得完整 URL 时标注“直达链接未返回”，不得伪造或输出相对链接。此链接要求不授权输出原始页面正文、评论、附件或原始 MCP 载荷。`customer` 输出和 internal 分析中的“客户回复口径”仍禁止内部链接。

## MCP 边界

- 所有连接器只调用名称、description 和输入 schema 均明确只读的工具。
- ZCode 当前不执行 Codex 的 `enabled_tools`、`disabled_tools` 或 `default_tools_approval_mode` 字段；插件不得声称这些客户端白名单在 ZCode 中生效。
- 当前会话出现创建、更新、删除、评论、合并、推送、分配、转换等写能力时，记录警告并拒绝在查询/连通检查中调用。
- BBS 的 `bbs_create_thread` 只有在用户明确要求经验回流、完成查重与脱敏、审核最终内容并再次确认发布后才可调用。
- 工具可见或初始化成功不等于可用；只有当前会话中的明确只读工具成功返回结构化结果，才记录“结构化查询成功”。
- 只读调用也不得输出 Token、Authorization、原始 MCP 载荷或未过滤提供者 JSON。
- Atlassian 只使用共享远端 `zstack_atlassian_shared`；不回退到旧本机适配器或旧内部目标。

## 仓库提交规则

允许提交：

- 工作流、模板、脱敏规则和只含占位符的配置示例；
- 仅引用环境变量且通过校验的共享 MCP 配置；
- 不含真实案例内容的链接模板和受控端点配置。

禁止提交：

- `.env`、Token、密码、Cookie、私钥、授权头或许可证文件；
- 客户原始日志、截图、抓包、dump、CSV/XLSX、DOCX/PDF、ZIP/RAR/HAR、客户填充后的文档或生成报告；
- Jira/Confluence 原文、评论、附件、批量导出或写操作痕迹；
- 内部支持归档、支持 SQL、内部 GitLab、CRM 或私有客户数据库内容；
- 未批准内部端点、真实账户、原始 MCP 载荷、提供者 JSON 或缓存产物。

经内容与元数据清理、只包含占位符且作为技能运行必需资产的标准 DOCX/PDF 模板可以提交。客户填充文档和生成报告仍禁止提交。仓库禁止客户/生成文档，不等于分享检查按扩展名一刀切；检查待分享文档时必须检查实际内容和元数据，文件类型本身不是失败理由。

## 文档分享检查

对 DOCX、PDF、XLSX 等容器或二进制文档，至少检查：

- 正文、页眉页脚、批注、修订、隐藏内容和附件/嵌入对象；
- 超链接与关系文件中的内部 URL；
- 作者、最后修改者、公司、模板路径、自定义属性、打印/修订历史等元数据；
- 客户名称、项目名、UUID、IP、账号、主机名、许可证衍生身份；
- 对分析记录和 `internal` 交接，关键断言是否显式包含公开标签、E0-E5 成熟度、来源类型和证据边界。
- `customer` 正式报告可以不展示内部标签，但根因、影响和修复断言必须能回溯到已标注的源分析，并通过无依据断言检查。

无法解析或无法检查关键区域时标注“检查未完成”，不能判定通过。经过内容脱敏、元数据清理且符合目标受众规则的生成文档可以分享，但是否可提交仓库仍受仓库提交规则限制。

## 发布检查

- 不存在真实凭证、许可证、原始客户证据或生成输出；
- 受控 HTTP 端点仅出现在允许位置，且未被描述为 TLS 或加密链路；
- 所有外部查询规则都要求先去标识化；
- MCP 工具调用遵循 ZCode 权限与技能安全约束，查询/连通检查拒绝写工具；
- 交接和脱敏输出明确标注 `internal` 或 `customer`；
- 分析记录和 `internal` 交接的关键断言分别标注来源类型、公开标签和 E0-E5 成熟度；`customer` 正式报告的关键结论可回溯到这些源断言；
- E5 只用于当前事件完成修复后验证闭环。
