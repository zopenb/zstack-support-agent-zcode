# 脱敏检查

检查待分享文档或摘要，并给出面向指定受众的通过、未通过或检查未完成结果。

## 第零步：强制选择受众

开始检查前必须得到且只选择一个值：

```text
受众：internal
```

或：

```text
受众：customer
```

如果用户没有指定且上下文无法明确确定，不开始检查、不猜测默认值，只询问“请指定受众为 internal 或 customer”。最终结果始终重复写出受众，不使用无受众限定的通过语句。

## 共同检查项

两种受众都检查：

1. Token、密码、Cookie、私钥、Authorization、`.env` 值和可逆凭证；
2. 许可证密钥及许可证衍生的客户身份；
3. 不必要的客户/项目/租户名称、UUID、IP、MAC、域名、主机名、账号、邮箱和序列号；
4. 原始日志、截图、抓包、dump、命令完整输出、附件和未过滤提供者 JSON；
5. Jira/Confluence/BBS 原文、评论、附件、批量导出和 MCP 原始载荷；
6. 对分析记录和 `internal` 交接，关键断言是否同时包含“已确认/较可能/可能/证据缺失”、E0-E5 成熟度、来源类型和证据边界；
7. E0-E2 是否被写成当前事件最终根因，修复提交/发布/Jira 关闭是否被误标 E5；
8. “已关闭”是否有当前事件 E5 恢复验证和关闭验收条件。

## 受众差异

### internal

- internal 事件分析或交接声称 BBS/Jira/Confluence 已命中时，必须包含标题摘要和合规 Markdown 直达链接，或明确标注“直达链接未返回”；不得伪造或退化为相对/伪链接。
- 禁止内部原文、评论、附件、账号、凭证和无关客户标识。
- Atlassian 受控端点 `http://172.18.250.27:3340/mcp` 只在连接器配置或内部运维诊断确有必要时允许；一般案例和交接仍应删除。

### customer

- 禁止 BBS/Jira/Confluence 链接、内部 IP/URL、内部系统入口和内部拓扑。
- 内部编号、标题或状态仅在已有明确对外批准时保留，否则改为脱敏描述。
- 客户名称、项目名和联系人默认泛化。仅当文件明确直接交付给同一客户、用户确认收件对象且版式确有需要时，才允许最小保留该收件客户自身标识；这类文件仍不可公开、跨客户复用或包含第三方标识。
- 禁止内部操作细节、研发评论、私有版本规划和仅供内部使用的风险判断。
- 只保留客户可验证的事实、适用边界、批准口径和客户安全行动。
- 正式客户报告可以不显示内部 E0-E5 标签，但根因、影响和修复断言必须能回溯到已标注的源分析；逐项检查是否有依据、是否超出源断言范围。无法获得源分析且无法验证关键结论时标记“检查未完成”，不要强制把内部标签写进客户正文。

## DOCX、PDF 与其他文档

不得因扩展名是 DOCX、PDF、XLSX 或生成报告就直接判定失败。文件类型不是脱敏结论；应检查实际内容和容器元数据。

按格式能力检查：

- 正文、页眉页脚、脚注、批注、修订、隐藏文本/工作表和表单字段；
- 超链接及关系文件中的内部 URL；
- 作者、最后修改者、公司、模板路径、自定义属性、打印/修订历史；
- 嵌入对象、附件、缩略图和可能保留原始材料的媒体；
- 可复制文本、OCR 文本与可见渲染是否一致。

无法解析文件、无法检查关键区域或渲染与提取结果冲突时，将对应项标记“检查未完成”，不得判定通过。内容和元数据均符合目标受众规则的生成文档可以分享；这不代表允许提交到源码仓库。

## 输出

```text
## 脱敏检查结果

受众：internal / customer

| 检查项 | 状态 | 问题位置 |
|--------|------|----------|
| 凭证与密钥 | 通过/未通过/检查未完成 | |
| 许可证内容 | 通过/未通过/检查未完成 | |
| 客户标识与原始数据 | 通过/未通过/检查未完成 | |
| 内部系统内容与链接 | 通过/未通过/检查未完成 | |
| 文档隐藏内容与元数据 | 通过/未通过/检查未完成 | |
| 证据标签或源分析可追溯性 | 通过/未通过/检查未完成 | |
| 根因和 E5/关闭声明 | 通过/未通过/检查未完成 | |

## 需要修改的部分

（只列类别、位置、受众规则和修改建议，不回显敏感值。）

## 结论

可在 internal 渠道分享 / 可向 customer 分享 / 不可分享 / 检查未完成
```

只有所有必检项均通过时才输出对应受众的“可分享”。任何未通过项输出“不可分享”；任何关键项无法检查时输出“检查未完成”。

完整标准以 [渠道安全策略](../ZStack%20Support%20Knowledge/references/security-policy.md) 为准。
